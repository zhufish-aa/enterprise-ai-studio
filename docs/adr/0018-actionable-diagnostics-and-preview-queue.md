# ADR 0018：可操作错误、历史预览诊断与查询排队

状态：Accepted

生成站点可能把参数、网络或并发异常都写成“检查权限”；旧源码不可修改，单独更新新站点不能改善历史版本。多个图表并发时直接拒绝第三个请求也会产生假失败。

保留 OpenAPI Error 的 code、message、requestId、可选 traceId 和 details[{field,reason}]。服务端提供具体字段原因，SDK、工具与RPC保留编号并补充修复建议；不复制原始驱动异常和提交的参数值。

iframe结果保留 error 字符串兼容旧SDK，同时附 diagnostic 给新SDK。预览父页面直接捕获并显示失败查询，因此旧源码即使吞掉异常，也可查看平台诊断。正常分享页不增加平台顶栏或重复标题，诊断仅在失败时出现。

网页与插件使用同一队列，两个实际并发、最多64项在途及等待请求；额外图表排队，取消等待项不发出API请求。主动取消不显示为查询失败。服务端权限与资源限制不变。

timeRange 的字段仍必须与不可变版本中登记的查询一致；修复追加新源码版本和构建，更新分享版本，保留历史版本。管理员身份不替代有效查询配置。

真实 PostgreSQL 验证缺少日期绑定时不创建任务、字段错误和追踪号可见、修正版本后得到准确统计。SDK验证超时/取消/非JSON和错误脱敏，队列验证7个图表全部执行及取消。真实Harness宿主调用仍由用户验收。

后续决策：原64项前端等待上限和服务端在途拒绝已由[ADR0020](0020-query-admission-and-scheduling.md)替代，以当前调度实现为准。
