# ADR 0019：查询行数由请求决定

状态：Accepted

旧 TEST 策略把 maxRows=1000 当成硬上限，并在创建源码版本时验证查询，导致一个合法的 5000 行查询直接阻断整个项目提交。游标另有 10000 行累计终点，业务不能继续分页。这些默认数字不表达数据权限，用户明确要求取消。

TEST 查询和导出按调用者显式 limit/pageSize 执行；两者均省略时不添加 SQL LIMIT。底层执行计划以 rowLimit=0 表示未指定上限，编译器不生成 LIMIT/OFFSET，结果处理不截成零行。显式分页仍取 pageSize+1 判断后续数据，游标不再有 10000 行终点。输入数字须可精确表示为非负安全整数；公开 limit/pageSize 仍须为正整数。

QueryPolicyInput/QueryPolicy 的 maxRows/maxExportRows 保留为可选废弃字段，以兼容不可变旧策略。授权链不再将这些字段用于 TEST 行数比较或源码提交校验。QueryValidation.maxRows 可为 null。迁移 0010 只删除 query_jobs.row_count 的 10000 上界，保留非负检查和现有记录。

生产消费仍读取已批准发布范围；数据集、字段、部门及行权限不由行数决定。响应字节、超时与数据库资源机制独立存在，本决定不声称物理资源无限。

已完成契约生成、必要编译、运行服务更新和插件打包安装。用户要求本次不再运行验证，由用户自行验收；新增/调整的回归测试没有在此变更后执行，不能引用此前测试通过数证明此变更。
