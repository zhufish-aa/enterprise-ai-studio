# ADR 0021：冻结审批、受控静态部署与原子激活

状态：Accepted

阶段06沿用不可变源码/报表版本和统一查询网关。一个上线申请冻结源码与构建哈希、完整manifest、TEST结果声明、版本化数据结构要求、语义策略、字段/指标、敏感字段、目标部门和成员，以及申请表中选择并经服务端验证的顺序审批人。2026-10-24根据用户反馈，取消先到独立设置配置流程的前置步骤：申请表直接选人、添加/排序阶段，旧应用流程仅为可修改预填和旧客户端兼容。选择负责审核的人与伪造实际审核身份是两个不同字段边界；实际审批身份仍来自当前登录会话，请求不能提交approved或生产连接。草稿即冻结内容；修正版本或范围时创建新申请，避免修改已审核事实。

同日取消“提交申请前必须已有生产映射”的错误前置条件：申请冻结逻辑数据要求expectedSchema，允许release_scopes.mapping_id为空；在创建实际部署时才解析、校验并固定deployments.mapping_snapshot。映射快照由数据库触发器禁止改写；runtime_grants的外键继续绑定批准的版本、数据集范围，额外触发器要求实际mapping与本次部署快照及同一逻辑源的production映射一致。旧审批已经绑定的映射不解冻、不替换。没有生产映射/服务仍不能实际部署，但可以先提交与审批，不发假授权，也不重用TEST映射。

审批步骤在申请表直接配置，不强制额外审批人数或固定组织角色名称；新表单默认显示一个审批人，可按实际业务添加、移除和排序。同一人员可以承担多个阶段，申请人始终不能自审。stepIndex和不可变approval_records实现顺序与重复请求识别，当前角色与成员状态实时检查。密码登录的正常人类成员可以按当前RBAC审批；AI个人令牌只能代为提交和查询，不能审批或执行正式发布。

合法查询延续ADR0019/0020，不新增返回行数、在途数量、上线申请次数、固定失败重试次数或默认审批有效期配额。release_scopes.max_rows可空，表示没有额外行数要求；访问范围由批准字段、指标、行策略和当前访问者授权共同决定。

测试build_jobs保持preview_only，不修改旧构建标志。独立deployment-worker仅接收签名固定静态HTML及哈希，检查CSP、摘要并原子落盘，再独立读回作健康检查，产生opaque-static-v1凭证；不执行上传脚本、Shell或服务端用户代码。API验证签名响应并把凭证写入immutable deployment_artifacts。生产消费者要求该凭证及批准事实，不能仅靠预览构建进入生产。

生产schema由环境专用connector通过mTLS领取部署租约指定的元数据计划，实际读取批准对象，核对当前列类型和可空性；API不连接业务DB。授权/激活前后重新检查当前申请人资源授权、策略、映射、审批人和部署操作人。失败不触碰活动slot；成功在一个元数据库事务内写部署凭证、runtime_grants、撤销旧部署授权、更新slot和追加事件。发布重试复用唯一deployment，leaseToken避免过期回调激活。静态工作目录部分成功可按同一任务覆盖重做，不存在业务数据迁移回滚。

回滚选择仍有效的历史批准版本，创建新冻结申请，执行当前审批与部署流程。旧授权不恢复，外部业务数据不回滚。

本阶段验证采用独立PostgreSQL模拟生产集群，真实TLS/mTLS、独立只读账号与进程；TEST销售额47040、正式验收库94080，明确区分路由。当前验收范围是静态React/ECharts网站和PostgreSQL查询；不是通用Node站点托管、企业PKI/OIDC/Vault、漏洞扫描/SBOM、内核沙箱或真实业务生产库验收。
