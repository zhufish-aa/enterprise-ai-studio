# ADR-0001：模块化单体与独立执行边界

日期：2026-10-22 · 状态：Accepted

## 背景

身份、资源、审批、部署和授权具有强事务关系；首期团队规模与内网运维条件不适合大量服务自治。AI 源码构建与数据库查询又需要不同网络、秘密和故障边界。

## 决策

控制面采用 NestJS + Fastify 模块化单体，明确 Identity、Applications、Catalog、Reports、Releases、Queries、ApplicationData 和 Audit 的表归属与应用服务。只有基础设施端口共享，不跨域读取私有实现。查询与构建采用独立 worker/专用执行池；生产与测试分开身份和主机。控制面不执行代码、不连接业务数据源、不挂载 Docker socket。

## 替代与后果

纯 Fastify 更轻，但需自建领域组织约定；全微服务增加审批分布式事务和部署成本；全部进程内执行不能形成隔离。单体部署共享故障域，需依靠资源限额与执行外置减轻；后续可按稳定领域端口拆服务，无需提前引入分布式事务。

## 验证

工作区依赖检查阻止应用反向引用；后续网络测试证明构建器不能触达控制面、测试池不能触达生产。普通 Compose 不构成不可信代码隔离证明。
