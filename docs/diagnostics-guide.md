2026-10-24补充：插件0.2.1起，原生“构建此版本”按钮改为调用SDK的无请求体POST。后续用户截图仍有同一400；只更新插件磁盘文件没有覆盖宿主当前注册的旧按钮调用。当前后端契约增加可选StudioBuildCommand，明确兼容省略请求体和空JSON对象{}，因此旧按钮也不再因为空对象被拒绝；非空字段继续按additionalProperties:false校验，鉴权与构建流程不变。没有要求用户改参数或先重启插件才可构建。preview在资源鉴权后区分BUILD_NOT_STARTED、BUILD_IN_PROGRESS、BUILD_FAILED、BUILD_ARTIFACT_UNAVAILABLE，不把缺少构建产物误报为通用404。上线申请直接使用所选版本的成功buildJobId，不为获取ID强制下载预览HTML。申请页提供构建与预览动作，提交前可自动构建同一不可变版本，重复构建点击复用正在执行的任务。

网页、TypeScript SDK 和 Harness 工具错误包含操作、具体原因、处理方法、错误码、HTTP 状态以及服务端返回的请求/追踪编号。参数错误附字段路径与格式说明，不回传提交的字段值。未知错误显示具体操作和编号，并明确原因尚未确定，不把网络、参数或构建错误统一归为权限不足。

## 日期筛选

iframe 的 query(queryKey,filters,timeRange) 只能使用当前应用版本已经登记的查询。每个会接收 timeRange 的查询都需要在 studio.manifest.json 的对应 query 下登记 timeRange，fieldKey 必须相同；区域、产品或客户汇总即使不按日期分组，也需要登记。缺失时返回 422 INVALID_FILTER_BINDING，details 指出查询名及 timeRange.fieldKey。补充清单、提交新版本并构建后生效；历史源码和产物不修改。

## 历史版本与错误展示

平台预览层直接捕获失败的查询，显示浮动诊断面板，可复制全部错误信息和收起详情。即使旧版生成代码 catch 后只显示“检查权限”，仍能从平台面板看到真实错误；不依赖重新修改旧版源码。面板仅在查询失败时显示，正常分享页全屏显示站点本身，不显示平台顶栏和重复标题。身份与数据权限仍由 API 实时验证。

多个图表可同时请求，网页和 Harness 预览桥排队执行，默认实际并发为 2，等待队列不设 64 项数量拒绝。后台不再因每用户2条或组织8条在途请求而拒绝业务查询；已授权请求进入持久队列，执行端忙碌时等待。取消尚未执行的请求不会发出 API 查询，页面卸载取消执行中的请求。新版预览桥持续读取任务至终态，并给等待中的新版SDK发送心跳，避免固定轮询次数或排队时间产生假超时。

## Harness 插件

插件 0.1.9 的工具错误为 ok:false,error:{code,message,action,operation,status?,requestId?,traceId?,details?}。非法参数会指出缺少或类型错误的字段；原生界面显示完整说明并可复制。请求超时、主动取消、后台无法连接、HTML/非 JSON 响应分别诊断。原生 RPC 保留服务端字段详情和编号；日志仅记录工具、状态、代码等元数据。Skill 已补充日期清单和错误保留规则。

真实 Harness 宿主和 Agent 工具调用仍由用户验收；包构建、安装校验和 SDK 测试不能代替宿主验收。
