# 风险分析与安全设计

## 1. 资产、攻击面与授权原则

保护对象包括企业生产数据、数据源凭据、用户会话、审批真实性、不可变制品、托管业务记录及审计证据。不可信输入包括 AI 源码/依赖、报表配置、上传归档、工具参数、浏览器消息、筛选值和队列消息。企业内网不等于可信调用方。

默认拒绝。所有生产控制由后端执行，前端菜单和插件提示不能作为权限边界。身份、组织、资源动作、当前部署、数据授权和行策略必须同时成立。RBAC 决定可执行动作，资源 grant/成员/受众约束目标，runtime_grant 约束部署对生产数据的能力；三者不能相互替代。

## 2. 风险、防护与验证矩阵

| 风险 | 明确边界与防护 | 必测攻击 / 预期结果 |
| --- | --- | --- |
| AI 任意执行代码 | API 只存取源码；构建在独立主机 gVisor/microVM；无网络、无 Docker socket、无秘密、非 root、只读根目录、临时工作盘、资源限额 | 读取宿主文件、fork bomb、磁盘填充、逃逸、连接控制面/元数据地址均失败；超时强制销毁 |

## 3. 生产查询授权算法

1. 验证当前用户、交互会话、有效组织成员与账号状态，拒绝由客户端声明的 userId/department/角色。
2. 服务端解析 app 当前 production deployment_slot，校验 active 状态、应用受众以及 report.view/app.use 动作；报表还必须出现在该 AppVersion 固定引用中。
3. 解析不可变 ReportQuery 或应用 QuerySpec，只允许其固定 dataset_version。读取该 deployment 的 active runtime_grant、release_scope、有效期、policy_epoch；检查审批快照及当前源状态。
4. 确认 scope 的 mapping 仍是该 logical source 的 production head、连接仍有效、schema digest 匹配；未知或变更一律拒绝。
5. 取字段/指标/筛选/行策略/成本的交集。行策略依据可信身份属性求值；缺少属性时拒绝，不能回退到“全部组织数据”。
6. 编译受控参数化计划，创建有界 query_job 和 outbox。worker 只接任务 ID，执行前通过独立身份获取短租约计划并重验 epoch/grant，不把 Redis 消息当授权证明。
7. 生产 worker 用专属网络、TLS 和秘密身份读取指定视图，强制只读事务、statement_timeout、行数/字节/并发限额。完成后清理连接的事务与会话状态，防止连接池残留身份。
8. 结果交付再次检查用户/epoch/grant/slot；撤销后不交付在途结果。取消数据库执行并销毁过期结果对象。

因此发布审批提供的是应用执行范围上限，当前访问者权限与行属性决定实际可见数据。开发者自己的测试数据集授权不自动传播给浏览者；浏览者也不需要获得创建者的个人数据库角色。

## 4. 审批、撤销与回滚

审批快照涵盖 source/artifact/template/lock 摘要、app/report/dataset 版本、映射修订、schema/行策略摘要、字段/指标范围、数据分类、受众、成本上限、托管集合 actions/schema 和审批策略。snapshotDigest 使用规范化 JSON 的 SHA-256，字段顺序不能导致语义相同请求产生不同结果；快照封存后不变。

审批人必须是配置策略要求的当前负责人，且不等于申请人。交互审批校验企业登录的 amr/acr 和 auth_time（建议5分钟内强化认证）；模型工具和客户端自报 human=true 无效。审批权限与发布执行权限分离，修改角色也不能使历史审批自动满足新策略。

撤销事务更新 grant、policy_epoch、审计与取消事件。API/worker 缓存授权最多30秒，并依赖推送失效；结果交付强制读权威 epoch。目标为撤销提交后不再有新结果交付，在途查询尽快取消，取消延迟需实测；数据库已开始的读取不能宣称被物理撤回。关键身份服务不可用时拒绝新生产任务。

回滚仍需新申请、新审批、新部署和新授权。旧版本的已撤销 grant、失效受众和过期批准不能复活。应急恢复可以暂停应用或立即撤权，不设置绕过审批直连生产的“紧急模式”。

## 5. SSRF、秘密与运行网络

企业业务库通常位于私网，因此不能简单禁止全部 RFC1918 地址。采用企业批准的 endpoint 清单：精确 host/port、环境、DNS 解析允许 CIDR、TLS server name 和数据库名。连接测试与查询均复用同一验证器；拒绝 loopback、link-local、metadata、控制面/管理网和未注册地址。DNS 变化不自动扩大授权，解析后固定连接 IP，同时验证原始主机的证书，避免校验后再次解析。

生产/测试 Vault 路径由 worker 身份决定，任务参数不能覆盖 secret mount。SecretRef 只允许管理员提交批准命名空间；日志连引用路径也需脱敏，防止泄露系统拓扑。凭据在进程内短驻留，轮换后回收连接池；不能放进队列 payload、AI 上下文、静态制品或应用环境变量。

控制面、构建器、测试查询器、生产查询器和静态服务之间采用最小允许连接矩阵。构建器 network=none，只使用预热依赖缓存；生产查询器仅可访问内部授权服务、指定 Vault 地址、指定生产库及结果存储。普通 Compose network internal 无法替代生产防火墙和实际沙箱验证。[Compose 网络行为](https://docs.docker.com/compose/how-tos/networking/)

插件只在个人profile使用当前用户Token，上传要官方ApprovalService allowed-once；配置、工具参数和模型输出不包含Token。工作区文件采用允许后缀、真实路径、硬/软链接和大小检查；Windows目录竞态与reparse攻击仍需宿主验收。真实Harness工具调用与秘密存储由用户验证，未声称通过。



## 分享与个人令牌已接通的拒绝边界

组织内公开不等于匿名或公网。分享revision/version/build与访问者当前授权在服务端重验，不借用创建者Token。私有撤回后旧proof和查询结果拒绝。个人令牌只有read/develop，组织绑定、委托客户端身份、权限交集和实时撤销；不允许管理/审批/生产或再签发。一次性秘密不写幂等响应、审计或浏览器持久存储。Harness never仍拒绝AI上传，用户可在站点页主动检查固定快照再确认；不会将Agent拒绝当作授权。宿主真实测试由用户执行，OS无限shell/网络/生产沙箱仍属未验收边界。详见新增使用说明及ADR。


## 账号密码登录已接通

网页不再使用令牌输入表单。新增scrypt、只存摘要的8小时HttpOnly/Strict Cookie、Origin+CSRF、服务端首次改密、数据库限流、退出及改密会话撤销；网关保存内部会话ID并在执行/结果读取重验。单因素密码会话不允许生产查询/诊断/审批，资源授权不能超出调用者权限。管理员离线产生，无默认弱密码/公共管理员抢占。邀请注册只能普通业务角色，消费时重新检查邀请者当前权限。企业SSO/MFA/邮件找回和部署入口层策略仍未验收。
