# AI 辅助开发约束

## 设计和实现顺序

先确定资源归属、身份来源、信任边界、状态机与失败行为，再编写接口与持久化。每个生产访问能力必须有后端拒绝路径及相应测试。API 的业务字段不得直接接收 `userId` 作为调用者身份、`isAdmin`、`approved=true`、`environment=production` 或连接串。

数据源管理员只能注册企业网络清单中的 endpoint；开发者选择逻辑数据源和授权数据集。创建者、审批者、发布执行者和报表访问者分别鉴权。管理员配置角色也受授权上限限制，不能给自己创建无审计的审批捷径。

## 变更规则

1. 依据 OpenAPI 增加可验证 DTO/JSON Schema，拒绝未知字段；从 OIDC 或内部工作负载身份获取调用者。
2. 在事务内检查组织、资源权限、当前状态、revision、幂等记录及审批摘要，写业务事实和 outbox。
3. 不让 PostgreSQL 元数据库事务等待远程数据库或容器构建；worker 以不可变任务 ID 拉取授权任务，采用至少一次投递和幂等处理。
4. 所有回调检查 mTLS 身份、任务租约、attempt 和预期状态。超时、撤销、重复投递、worker 重启均须有确定结果。
5. schema、映射、角色、受众或行策略变更时递增 policy epoch，并使相关缓存与在途查询失效。

## 禁止实现

禁止在控制平面执行生成源码；禁止拼接用户 SQL；禁止让生成应用持有数据库凭据；禁止开发查询回退到生产连接；禁止通过直接更新部署指针绕过发布事务；禁止把创建者的个人数据库权限借给浏览者。

## 完成定义

契约与数据库设计一致，类型检查和构建通过；权限、跨组织访问、并发状态、撤销与错误脱敏均有测试。对尚未连接企业身份、秘密管理、生产网络和沙箱的能力明确标注未启用，不使用模拟成功响应掩盖未实现功能。
